## 1. Состояние проекта и реализованные функции

Проверено наличие точки входа, модулей приложения, тестов, зависимостей, документации, ресурсов, примеров и стартового скрипта. Обязательные файлы присутствуют.

- Настольное приложение на Python и PySide6/Qt Widgets с графитовым интерфейсом, синими акцентами и четырьмя разделами: Dashboard, Data Editor, Merge Files и History.
- Виртуальный просмотр DataFrame через `QAbstractTableModel`, без создания виджета для каждой ячейки.
- Dashboard: количество строк, столбцов, пропусков и повторяющихся строк.
- Импорт CSV: автоматический или ручной выбор кодировки, UTF-8/BOM, UTF-16 и распространённые legacy-кодировки; определение разделителей; сохранение пустых записей.
- Импорт XLSX с выбором листа, проверкой заголовков и обработкой ошибок чтения.
- Очистка: удаление дубликатов, полностью пустых строк, краевых пробелов в тексте; заполнение пропусков текстовым или числовым значением.
- Undo, Reset и отмена самого Reset; отслеживание экспортированного состояния.
- Объединение CSV/XLSX по строкам с выравниванием столбцов по именам, объяснением несовместимости, предпросмотром, экспортом и передачей результата в редактор.
- Экспорт CSV с UTF-8 BOM и XLSX; защита исходных путей и hard-link-алиасов; подтверждение перезаписи других файлов; запись через временный файл.
- Журнал операций текущего сеанса: время, операция, число затронутых строк, длительность и результат.
- Фоновые операции через `QRunnable`/`QThreadPool`; обновление интерфейса и моделей в GUI-потоке.
- Пустые состояния, индикатор загрузки, блокировка недоступных действий, уведомления, подтверждения и горячие клавиши.

## 3. Известная воспроизведённая ошибка

### Обрезание длинного текста при экспорте XLSX

Дополнительный диагностический запуск, не входящий в 56 pytest-тестов:

1. Создан DataFrame с одной текстовой ячейкой длиной **40 000** символов.
2. Выполнен `app.core.file_handler.export_file(...)` в XLSX.
3. Файл прочитан обратно через `read_file(...)`.
4. Длина прочитанного значения составила **32 767** символов.

Во время записи pandas выдал Python `UserWarning`: `Cell contents too long, truncated to 32767 characters`. Экспорт при этом завершился без исключения. В интерфейсе нет отдельной обработки этого предупреждения: пользователь может получить сообщение об успешном сохранении при сокращении значения.

Файл для первичной проверки: `app/core/file_handler.py`, функция `export_file`. При последующей доработке следует явно проверять предел длины ячейки до записи и сообщать пользователю о необходимости другого формата либо явного решения о сокращении данных. **В этом пакете ошибка не исправлялась**, чтобы независимая проверка получила исходное поведение.

Диагностический XLSX хранится только в исключённой папке `test-output/review/` и в архив не включён.

## 4. Ограничения и области для проверки

- **Автоматическое определение типов может изменить идентификаторы.** Дополнительно воспроизведено: CSV со значением `00123` импортируется как число `123`. Это уже описано в README как ограничение pandas type inference. Явного выбора типов столбцов при импорте нет; важны также точность чисел и значения `NA`/`NULL`.
- Приложение рассчитано на данные, помещающиеся в RAM. CSV читается целиком; преобразования и состояния Undo увеличивают расход памяти. Для больших файлов отдельного нагрузочного подтверждения нет.
- Undo хранит до 10 действий с мягким бюджетом 256 MiB на стек; как минимум предыдущее состояние сохраняется. Это не предел общей памяти приложения: оригинал, текущее и сохранённое состояния могут удерживаться отдельно.
- Отмена выполняющейся фоновой операции не реализована. Выбор файла и диалоги можно отменить, но после начала обработки требуется дождаться завершения.
- Таблица предназначена для просмотра. Прямого редактирования ячеек, поиска и фильтрации нет.
- История и изменения существуют только в текущем сеансе. Автовосстановления и сохранённых сценариев очистки нет.
- Экспорт XLSX создаёт один лист с данными. Оформление исходной книги, формулы, макросы, графики и остальные листы не переносятся. Формулы при импорте читаются по кешированным значениям; при отсутствии кеша возможны пропуски.
- Поддерживаются CSV и XLSX, но не XLS/XLSM и не защищённые паролем книги. Определение кодировок и разделителей эвристическое.
- Интерфейс англоязычный. Установщик и самостоятельный EXE не собраны.
- Локально проверена только указанная версия Python. `requirements-lock.txt` фиксирует окружение этой проверки; его переносимость на другие версии Python здесь не подтверждалась. CI для Python 3.11/3.13 подготовлен, но на GitHub не запускался.

## 7. Установка и запуск после распаковки

Для максимально близкого воспроизведения используйте Windows и Python 3.13. В PowerShell перейдите в распакованную папку `DataClean`, затем выполните:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe main.py
```

`requirements-lock.txt` включает также инструменты тестирования и анализа. Для установки только основных зависимостей можно использовать `requirements.txt`, но тогда версии будут выбраны заново в заданных диапазонах.

После создания окружения доступен запуск двойным щелчком по `start.bat`. Окружение в ZIP намеренно отсутствует: стартовый скрипт без предварительной установки не запустит приложение.

Для повторной проверки:

```powershell
.\.venv\Scripts\python.exe -m pytest -q --tb=short
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
.\.venv\Scripts\python.exe -m compileall -q app main.py tests examples tools
.\.venv\Scripts\python.exe -m pip check
```
